Goal
-----
Build a single-page web app (works on Replit) for **Driver Drowsiness Detection**. The camera must run in the browser and the app should detect whether the driver is sleepy or not. Avoid external APIs; prefer client-side ML. If any external model is used, it must be a free browser model (TensorFlow.js / MediaPipe). The UI must be clean, minimalistic, use a consistent color theme, include subtle micro animations, and be fully functional on desktop browsers (Chrome/Edge/Firefox). Provide a Python backend only as an optional component for logging/analytics — core detection must not depend on it.

Priority requirements
---------------------

2. Drowsiness detection uses:
   - Eye Aspect Ratio (EAR) for blink/eye closure detection.
   - Mouth Aspect Ratio (MAR) for yawning detection.
   - A short moving-window logic to declare drowsiness (e.g., if eyes closed for N consecutive frames or MAR > threshold repeatedly).
3. No paid APIs. Use TensorFlow.js face-landmarks model or MediaPipe face mesh in JS.
4. Minimal, modern UI: single-page, responsive, one color theme (choose a cool teal/dark or soft blue), minimal icons, micro animations (button hover, subtle pulse on alert).
5. Deployable on Replit with one command. Provide clear run instructions.

Functional specification — detection algorithm
---------------------------------------------
1. Use the chosen face landmarks detector to get 468 face landmarks (face mesh) or the 468/468-like points.
2. Eye Aspect Ratio (EAR):
   - For each eye, pick these landmark indices (or the equivalent from your model).
   - EAR = (||p2-p6|| + ||p3-p5||) / (2 * ||p1-p4||)
   - Compute EAR per frame and use average of left/right.
   - Use thresholds:
     - EAR_THRESHOLD = 0.23 (start here; provide easy calibration UI to adjust)
     - EAR_CONSEC_FRAMES = 15 (if EAR < threshold for 15 consecutive frames → drowsy)
   - Explanation: 15 frames @ 30fps ≈ 0.5s; you can tune to user preference.
3. Mouth Aspect Ratio (MAR) for yawning:
   - Define MAR similar to EAR using mouth landmarks (vertical/horizontal distances).
   - MAR_THRESHOLD = 0.6 and MAR_CONSEC_FRAMES = 10 (tunable).
4. Blink detection:
   - Count blinks (EAR falls below SHORT_BLINK_THRESHOLD and recovers) — optionally track blink rate.
   - Low blink rate + long closures = drowsy.
5. Final drowsy decision: If any of:
   - eyes closed for EAR_CONSEC_FRAMES, or
   - MAR exceeded MAR_THRESHOLD for MAR_CONSEC_FRAMES, or
   - average blink duration > BLINK_DURATION_THRESHOLD and blink frequency low.
6. Safety action: visually flash red alert, play loud beep (loop until user clicks snooze), display “ALERT: Driver Drowsy — Please Stop” message.

Key implementation details to include in the code
-----------------------------------------------
- Camera startup: navigator.mediaDevices.getUserMedia({video: {facingMode: "user", width: 640, height: 480}, audio: false})
- Hidden canvas: draw video frame to canvas each animation frame, pass canvas to the model detector.
- Model loop: use requestAnimationFrame for continuous detection.
- Performance: throttle detection to ~15–30 FPS; use model.estimateFaces or faceLandmarksDetector with 'mediapipe_facemesh' backend for speed.
- Calibration: a modal that asks user to look at camera, measures baseline EAR and MAR for 2–3 seconds, sets thresholds adaptively (recommended).
- Logging: optional local log array of incidents with timestamp. If a Python backend is present, POST incidents every minute (batch) using fetch to /api/incidents.
- Privacy: emphasize frames never leave the browser unless user opts to send logs.

Exact thresholds & tuning guidance (include in README)
-----------------------------------------------------
- Start with EAR_THRESHOLD=0.23, EAR_CONSEC_FRAMES=15.
- MAR_THRESHOLD=0.6, MAR_CONSEC_FRAMES=10.
- Provide UI sliders to let users tune these numbers.
- Suggest lower EAR_THRESHOLD for users wearing glasses, higher for heavy eyelids. Offer calibration step.
